# Список команд, которые могут пригодиться перед установкой системы:

## Просмотр всех разделов на диске

```bash
# Метод 1: использование fdisk
fdisk -l

# Метод 2: использование lsblk
lsblk

# Метод 3: использование parted
parted -l

# Метод 4: использование блоковых устройств через /proc
cat /proc/partitions
```

## Просмотр сабволюмов btrfs

```bash
# Метод 1: использование btrfs-команды для смонтированной файловой системы
btrfs subvolume list /mount/point
```
Данная команда работает также с любой точкой монтирования для любого из сабволюмов целевой фс. Т.е. достаточно указать точку монтирования любого из сабволюмов или смонтировать в любое место любой из них, если ни один не смонтирован.
```bash
mount -o subvolid=0 /dev/имя_устройства /mnt/каталог_для_монирования
# или
mount -o subvol=@любой_существующий_сабволюм /dev/имя_устройства /mnt/каталог_для_монирования
# или
mount /dev/имя_устройства /mnt/каталог_для_монирования

```
## Форматирование раздела в качестве физического тома LVM

```bash
# Создание физического тома
pvcreate /dev/sdXY

# Проверка созданного тома
pvdisplay /dev/sdXY
```

## Форматирование раздела в btrfs

```bash
# Метод 1: основное форматирование
mkfs.btrfs /dev/sdXY

# Метод 2: форматирование с указанием метки
mkfs.btrfs -L "метка_раздела" /dev/sdXY

# Метод 3: установка определенного размера сектора
mkfs.btrfs -s 4k /dev/sdXY
```

## Создание группы томов LVM

```bash
# Создание группы томов
vgcreate имя_группы /dev/sdXY

# Создание с использованием нескольких устройств
vgcreate имя_группы /dev/sdXY /dev/sdZW
```

## Добавление физического тома в группу томов

```bash
# Добавление физического тома в существующую группу
vgextend имя_группы /dev/sdXY
```

## Удаление логического тома LVM для увеличения свободного места в группе томов

```bash
# Остановка всех процессов использующих том
fuser -km /dev/имя_группы/имя_тома

# Размонтирование тома если он смонтирован
umount /dev/имя_группы/имя_тома

# Удаление логического тома
lvremove /dev/имя_группы/имя_тома
```

## Создание нового логического тома LVM и форматирование его в btrfs

```bash
# Создание логического тома указанного размера
lvcreate -L 10G -n имя_тома имя_группы

# Форматирование созданного тома в btrfs
mkfs.btrfs /dev/имя_группы/имя_тома
```

## Уменьшение размер логического тома LVM

```bash
# Проверка текущего размера и использования
df -h /путь/к/точке/монтирования
lvdisplay /dev/имя_группы/имя_тома

# Размонтирование тома (если он смонтирован)
umount /путь/к/точке/монтирования

# Проверка файловой системы на ошибки
# Для ext4:
e2fsck -f /dev/имя_группы/имя_тома
# Для btrfs:
btrfs check /dev/имя_группы/имя_тома

# Уменьшение размера файловой системы
# Для ext4:
resize2fs /dev/имя_группы/имя_тома 10G
# Для btrfs:
btrfs filesystem resize 10G /путь/к/точке/монтирования

# Уменьшение размера логического тома
lvreduce -L 10G /dev/имя_группы/имя_тома

# Варианты для подгонки размера LV под фактический размер ФС:
# Вариант 1: с использованием fsadm (универсальный)
lvreduce -L$(fsadm -y size /dev/имя_группы/имя_тома) /dev/имя_группы/имя_тома

# Вариант 2: автоматический с помощью lvreduce --resizefs (для ext4)
lvreduce --resizefs -L 10G /dev/имя_группы/имя_тома

# (рекомемедуется !!!) Вариант 3: совмещение уменьшения ФС и LV с помощью lvresize (для ext4)
lvresize --resizefs -L 10G /dev/имя_группы/имя_тома

#Преимущества:
#Одна команда вместо двух (resize2fs не требуется)
#Автоматически изменяет размер и LV, и файловой системы
#Безопаснее, так как операции выполняются в правильном порядке
#Работает как для увеличения, так и для уменьшения


# Вариант 4: использование lvresize для уменьшения размера до заданного
lvresize -L-5G /dev/имя_группы/имя_тома

# Монтирование тома обратно
mount /dev/имя_группы/имя_тома /путь/к/точке/монтирования
```

### Лучшие варианты:
1) Для ext4 (и других стандартных ФС):
``` bash
lvresize --resizefs -L 10G /dev/имя_группы/имя_тома
```
Преимущества:
* Одна команда вместо двух (resize2fs не требуется)
* Автоматически изменяет размер и LV, и файловой системы
* Безопаснее, так как операции выполняются в правильном порядке
* Работает как для увеличения, так и для уменьшения

2) Для btrfs:
```bash
lvresize -L размер /dev/имя_группы/имя_тома
btrfs filesystem resize max /путь/к/точке/монтирования
```
Для btrfs нужны две команды, так как btrfs имеет свой механизм изменения размера.

* Остальные варианты менее предпочтительны:
lvreduce и lvextend - устаревший подход, требует отдельного resize2fs
* fsadm - более сложный синтаксис, хотя и универсальный инструмент
* lvresize -L-5G (с минусом) - менее очевидный синтаксис, легко ошибиться
Важно:
1) При уменьшении размера ext4 всё равно требуется предварительное размонтирование и проверка e2fsck
2) При использовании --resizefs предварительный resize2fs не требуется
3) btrfs можно изменять "на лету", но рекомендуется делать балансировку при уменьшении


## Увеличение размера логического тома LVM

```bash
# Проверка текущего размера и использования
df -h /путь/к/точке/монтирования
lvdisplay /dev/имя_группы/имя_тома

# Варианты увеличения размера логического тома:
# Вариант 1: добавление конкретного объема
lvextend -L +5G /dev/имя_группы/имя_тома

# Вариант 2: установка конкретного размера
lvextend -L 20G /dev/имя_группы/имя_тома

# Вариант 3: использование всего свободного места в группе томов
lvextend -l +100%FREE /dev/имя_группы/имя_тома

# Вариант 4: автоматическое изменение размера ФС (для ext4 и других) одной командой
lvresize --resizefs -L +5G /dev/имя_группы/имя_тома

# Вариант 5: автоматическое использование всего свободного места с изменением ФС
lvresize --resizefs -l +100%FREE /dev/имя_группы/имя_тома

# Увеличение размера файловой системы (если не использовали --resizefs выше)
# Для ext4 (можно выполнять на ходу):
resize2fs /dev/имя_группы/имя_тома
# Для btrfs (можно выполнять на ходу):
btrfs filesystem resize max /путь/к/точке/монтирования
```

## Примечания по изменению размера файловых систем

- **ext4**: 
  - Увеличение размера можно выполнять "на ходу" (без размонтирования)
  - Уменьшение размера требует размонтирования тома
  - Перед уменьшением необходимо выполнить проверку файловой системы (e2fsck)

- **btrfs**: 
  - Как увеличение, так и уменьшение размера можно выполнять "на ходу" (без размонтирования)
  - При уменьшении размера рекомендуется сначала выполнить балансировку файловой системы:
    ```bash
    btrfs balance start -dusage=90 /путь/к/точке/монтирования
    ```
  - После изменения размера может потребоваться синхронизация:
    ```bash
    btrfs filesystem sync /путь/к/точке/монтирования
    ```

## Удаление сабволюма из раздела или тома с btrfs для освобождения места на нём

```bash

# Проверяем смонтирован ли целевой сабволюм
mount | grep btrfs
# или
findmnt -t btrfs

# Размонтирование сабволюма, если он смонтирован
umount /путь/к/точке/монтирования

# Монтируем верхнеуровневый сабволюм (если от не смонтирован)
mount -o subvolid=0 /dev/имя_устройства /mnt/каталог_для_монирования

# Проверяем командой
btrfs subvolume list -a /mnt/каталог_для_монирования
# наличие вложенных сабволюмов и/или снапшотов и если они есть то сначала надо удалить их

# Удаление сабволюма по имени
btrfs subvolume delete /mnt//mnt/каталог_для_монирования/@целевой_сабволюм

# Если сабволюм защищён от записи (read-only), сначала снимите этот атрибут:
btrfs property set -ts /путь/к/сабволюму ro false

# Удаление сабволюма может не освободить место на диске сразу. Чтобы очистить пространство, может потребоваться выполнить балансировку или очистку:
btrfs filesystem sync /путь/к/файловой/системе

```
## Переименование логического тома LVM

```bash
# Проверка текущего состояния тома
lvdisplay /dev/имя_группы/старое_имя_тома

# Размонтирование тома (обязательно!)
umount /dev/имя_группы/старое_имя_тома

# Переименование тома
lvrename имя_группы старое_имя_тома новое_имя_тома
# или
lvrename /dev/имя_группы/старое_имя_тома /dev/имя_группы/новое_имя_тома

# Если том использовался в /etc/fstab, не забудьте обновить запись:
# /dev/имя_группы/старое_имя_тома -> /dev/имя_группы/новое_имя_тома

# Монтирование тома с новым именем
mount /dev/имя_группы/новое_имя_тома /путь/к/точке/монтирования
```

Важно: Том обязательно должен быть размонтирован перед переименованием. Если том используется как корневой или содержит важные системные каталоги, переименование нужно выполнять из live-системы или системы, которая не использует данный том.

## Создание нового раздела

### 📊 **Сравнение утилит разметки дисков**

| Утилита         | Интерфейс     | GPT / MBR | Скриптабельность | Работа с LUKS | Удаление сигнатур | Live-предпросмотр | Особенности |
|-----------------|---------------|-----------|------------------|----------------|-------------------|-------------------|-------------|
| `fdisk`         | CLI           | MBR / GPT | Средняя          | Нет            | Нет               | Нет               | Классическая, минималистичная |
| `cfdisk`        | TUI (curses)  | MBR / GPT | Нет              | Нет            | Нет               | Нет               | Удобный интерфейс для терминала 👍  |
| `gdisk`         | CLI           | GPT       | Средняя          | Нет            | Нет               | Нет               | Для GPT-дисков, как `fdisk` для MBR |
| `sgdisk`        | CLI           | GPT       | Высокая          | Нет            | Да (частично)     | Нет               | Скриптабельная версия `gdisk` |
| `sfdisk`        | CLI           | MBR / GPT | Высокая          | Нет            | Нет               | Нет               | Хорош для автоматизации |
| `parted`        | CLI           | MBR / GPT | Средняя          | Нет            | Нет               | Частично          | Поддерживает ресайз без удаления данных |
| `gnome-disks`   | GUI           | MBR / GPT | Нет              | Да             | Частично          | Да                | Простой GUI, создание и монтирование |
| `GParted`       | GUI           | MBR / GPT | Нет              | Нет            | Частично          | Да                | Мощная GUI-утилита на LiveCD  |
| `KDE Partition Manager` | GUI   | MBR / GPT | Нет              | Да             | Частично          | Да                | Альтернатива GParted в KDE |
| `udisksctl`     | CLI (D-Bus)   | MBR / GPT | Средняя          | Да             | Да                | Частично          | Обёртка над `udisks2`, используется в GUI |
|прочие|
| `wipefs`        | CLI           | —         | Да               | Да             | Да                | Нет               | Удаляет сигнатуры ФС и LUKS |
| `partx`         | CLI           | —         | Да               | Нет            | Нет               | Нет               | Обновляет partition table в ядре |
| `kpartx`        | CLI           | —         | Да               | Да             | Нет               | Нет               | Используется для маппинга разделов из `.img` |

Три основных подхода:
* Для создания разметки вручную в режиме юзер-френдли можно запустить cfdisk из TTY установочного диска Arch. 
* Можно также предварительно загрузиться с любого другого live-образа для использования GUI-утилиты.
* Если же нужно выполнить разметку автоматически при помощи одной команды, набора команд или скрипта, то нужно использовать скриптабильную утилиту (при необходимости предварительно прочитав её man)

```bash
# Метод 1: использование fdisk (интерактивно)
fdisk /dev/sdX
# Далее следовать инструкциям: n - новый раздел, выбрать тип раздела,
# указать начало и конец, w - записать изменения

# Метод 2: использование parted
parted /dev/sdX mklabel gpt
parted -a optimal /dev/sdX mkpart primary ext4 0% 100%

# Метод 3: использование sgdisk для GPT
sgdisk -n 1:0:+10G -t 1:8300 /dev/sdX
```

## Удаление ненужного раздела

```bash
# Метод 1: использование fdisk (интерактивно)
fdisk /dev/sdX
# Далее следовать инструкциям: d - удалить раздел, указать номер раздела, w - записать изменения

# Метод 2: использование parted
parted /dev/sdX rm 1  # Где 1 - номер раздела

# Метод 3: использование sgdisk для GPT
sgdisk -d 1 /dev/sdX  # Удаление раздела 1
```

## Создание криптоконтейнера luks с использованием пароля

```bash
# Создание LUKS контейнера
cryptsetup luksFormat /dev/sdXY

# Создание с указанием параметров шифрования
cryptsetup luksFormat --cipher aes-xts-plain64 --key-size 512 --hash sha512 /dev/sdXY
```

## Создание криптоконтейнера luks с использованием файла

```bash
# Создание ключевого файла
dd if=/dev/urandom of=/path/to/keyfile bs=4096 count=1
chmod 600 /path/to/keyfile

# Создание LUKS контейнера с ключевым файлом
cryptsetup luksFormat --key-file=/path/to/keyfile /dev/sdXY
```

## Открытие криптоконтейнера

```bash
# Открытие с вводом пароля
cryptsetup luksOpen /dev/sdXY имя_контейнера

# Открытие с использованием ключевого файла
cryptsetup luksOpen --key-file=/path/to/keyfile /dev/sdXY имя_контейнера

# После открытия контейнер становится доступен как /dev/mapper/имя_контейнера
```

## Его закрытие

```bash
# Размонтирование точки монтирования криптоконтейнера, если он смонтирован
umount /точка/монтирования

# Закрытие криптоконтейнера
cryptsetup luksClose имя_контейнера

# Проверка статуса (должен исчезнуть из списка)
ls -la /dev/mapper/
```

## Полная очистка диска для создания разметки с нуля

```bash
# Метод 1: быстрая перезапись нулями
dd if=/dev/zero of=/dev/sdX bs=4M status=progress

# Метод 2: безопасное стирание случайными данными
dd if=/dev/urandom of=/dev/sdX bs=4M status=progress

# Метод 3: использование shred
shred -v -n 1 /dev/sdX
```

## Создание новой таблицы разделов на диске

```bash
# Метод 1: создание GPT таблицы с помощью fdisk (интерактивно)
fdisk /dev/sdX
# Далее ввести g для создания GPT, w для записи

# Метод 2: использование parted
parted /dev/sdX mklabel gpt  # Для GPT
parted /dev/sdX mklabel msdos  # Для MBR/DOS

# Метод 3: использование sgdisk
sgdisk --zap-all /dev/sdX  # Очистка таблицы
sgdisk --clear /dev/sdX    # Создание новой GPT
```
