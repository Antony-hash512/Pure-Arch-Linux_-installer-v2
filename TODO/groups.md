
## Фиксация GID для системных групп в Arch Linux

Это абсолютно рабочий подход. В диапазоне **GID < 1000** (за исключением зарезервированных типа 0-root, 1-bin) сейчас "гуляет ветер", так как `systemd` по умолчанию аллоцирует ID сверху вниз (начиная с 999 и ниже) или использует высокие диапазоны.

Если вы пропишете эти группы в своём установщике **до** установки пакетов, которые их используют (или принудительно создадите их), то pacman и systemd просто подхватят уже существующие группы.

### Какие номера были "Олдскульными" (Static GIDs)?

Раньше (до перехода на динамические sysusers) в Arch Linux (и в старых Linux системах) часто использовалась такая схема (она похожа на текущую в Debian/Slackware):

| Группа | GID (Classic) | GID (Modern Arch) |
| --- | --- | --- |
| **tty** | 5 | 5 |
| **disk** | 6 | 6 |
| **lp** | 7 | 7 |
| **uucp** (serial) | 10 | ~986 |
| **log** | 19 | 19 |
| **video** | 33 (или 91) | ~985 |
| **audio** | 29 (или 92) | ~996 |
| **optical** | 93 | ~990 |
| **storage** | 95 | ~987 |
| **scanner** | 96 | ~991 |
| **power** | 98 | ~980 |
| **nobody** | 99 | 65534 (kernel overflow) |
| **users** | 100 | 100 |

*Примечание: В современном Arch `wheel` жестко закреплен на **998**, `adm` на **999** (хотя иногда `wheel` может быть 999). Их лучше не трогать, так как они прописаны в `sudoers` по умолчанию и в правилах Polkit.*

### Как реализовать это в установщике (Bash)

Самый "чистый" способ для современного Arch (чтобы `pacman` не ругался и не создавал `.pacnew` файлы) — использовать механизм **`sysusers.d`**.

Вы можете создать файл конфигурации, который скажет системе: *"При создании этих групп всегда используй эти ID"*.

Вставьте этот шаг в ваш скрипт установки (на этапе, когда вы уже находитесь в `chroot` или готовите файлы для него):

```bash
# Создаем файл пре-конфигурации для системных групп
# Путь внутри установленной системы: /etc/sysusers.d/00-static-groups.conf

cat <<EOF > /mnt/etc/sysusers.d/00-static-groups.conf
# Type Name     ID     GECOS           Home directory
g      uucp     10     -               -
g      video    33     -               -
g      audio    33     -               - # Часто audio и video объединяли, но лучше разделять
g      storage  95     -               -
g      users    100    -               -
EOF

```

*(Внимание: если вы хотите audio и video разными, дайте audio другой ID, например 29).*

Однако, `systemd-sysusers` отрабатывает при загрузке или установке пакета. Если вы хотите **железобетонно** закрепить ID прямо в момент установки, лучше использовать `groupadd` в цикле **до** установки основного софта (или сразу после установки базовой системы через `pacstrap`).

#### Функция для вашего Bash-скрипта

Вот пример функции для вашего установщика. Запускать её нужно внутри `arch-chroot` или применять к `/mnt`.

```bash
setup_static_groups() {
    echo "🔧 Setting up Old School static GIDs..."

    # Словарь: Группа -> GID
    declare -A groups=(
        ["uucp"]=10
        ["video"]=33
        ["audio"]=92
        ["optical"]=93
        ["storage"]=95
        ["scanner"]=96
        ["power"]=98
        ["users"]=100  # На всякий случай закрепляем
    )

    for grp in "${!groups[@]}"; do
        gid="${groups[$grp]}"
        
        # Проверяем, существует ли группа
        if getent group "$grp" >/dev/null; then
            # Если существует (например, создана пакетом filesystem), меняем GID
            groupmod -g "$gid" "$grp"
        else
            # Если не существует, создаем с нужным GID
            groupadd -g "$gid" "$grp"
        fi
        
        echo "  -> Group '$grp' set to GID $gid"
    done
}

```

### Преимущество такого подхода

Если вы зафиксируете ID в установщике:

1. У вас будет **единый стандарт** на всех ваших машинах.
2. Резервные копии (tar, rsync) будут переноситься между машинами без путаницы с правами доступа.
3. Это безопасно, так как диапазоны 10-99 в Arch Linux сейчас "свободны от обязательств" (системные ушли в 900+).

Единственное, что я советую **не менять** — это `wheel` (оставьте как есть в системе, обычно 998) и `network` (если используется), чтобы не конфликтовать со стандартными конфигами Polkit, которые могут ожидать дефолтных значений в некоторых редких случаях.

## Фиксация GID для группы wheel


В современном Arch Linux группа `wheel` действительно "плавает" между **998** и **999** (зависит от того, создается ли группа `adm` и в каком порядке ставятся пакеты). Закрепив её на **998**, вы избавитесь от этой случайности.

### Почему 998, а не 999?

В системе `systemd` принят негласный стандарт (который Arch соблюдает):

* **65534** — `nobody`
* **0** — `root`
* **999** — часто резервируется под `adm` (Administrator) или остается свободным "буфером".
* **998** — стандартное место для `wheel` в большинстве systemd-дистрибутивов.

### Обновленный код для вашего установщика

Добавьте `wheel` в тот же массив. Поскольку `wheel` — критически важная группа (нужна для sudo), создавать её **до** установки пакетов (`pacstrap`) или на самом раннем этапе настройки — отличная практика.

Вот полная версия функции для вашего Bash-скрипта, которая делает "красивую" олдскульную таблицу:

```bash
setup_static_groups() {
    echo "🔧 Setting up deterministic Group IDs..."

    declare -A groups=(
        # === Systemd / Admin ===
        ["wheel"]=998      # Sudo rights
        ["adm"]=999        # Admin logs monitoring
        
        # === Old School Hardware (Static) ===
        ["uucp"]=10        # Serial ports / RS-232
        ["video"]=33       # Graphics acceleration
        ["audio"]=92       # Sound cards
        ["optical"]=93     # CD/DVD drives
        ["storage"]=95     # Removable disks
        ["scanner"]=96     # Scanners
        ["input"]=97       # Input devices (evdev)
        ["power"]=98       # Power management
        
        # === Users ===
        ["users"]=100      # Default users group
    )

    for grp in "${!groups[@]}"; do
        gid="${groups[$grp]}"
        
        # Проверяем, существует ли группа
        if getent group "$grp" >/dev/null; then
            # Если уже есть - принудительно меняем GID
            current_gid=$(getent group "$grp" | cut -d: -f3)
            if [ "$current_gid" -ne "$gid" ]; then
                echo "  -> Correcting '$grp': $current_gid -> $gid"
                groupmod -g "$gid" "$grp"
            fi
        else
            # Если нет - создаем
            echo "  -> Creating '$grp' with GID $gid"
            groupadd -g "$gid" "$grp"
        fi
    done
}

```

### Когда запускать эту функцию?

1. **Идеально:** Сразу после `pacstrap` (установки базовой системы), войдя в `arch-chroot /mnt`.
2. Так как пакет `filesystem` (который является частью группы `base`) уже создаст основные группы при установке, ваш скрипт фактически будет выполнять ветку `groupmod` (исправление GID). Это нормально и безопасно на свежей системе, так как файлов, принадлежащих этим группам, еще практически нет.

Теперь у вас будет "золотой образ" системы, где на любом компьютере `ls -l /dev/snd` покажет одинаковые права, и вы сможете переносить бэкапы/конфиги без головной боли.
