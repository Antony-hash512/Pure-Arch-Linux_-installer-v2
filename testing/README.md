## Создание размеченного виртуального диска
Т.к. гитахаб не поддерживает бинарные файлы больше 100 мегабайт, для создания размеченного виртуального диска нужно запустить скрипт `./create_parted_qcow2.sh`

Он выведет на экран последовательность команд, которые нужно выполнить на виртуальной машине qemu
и запустит её.

Начало разметки нужно будет подтвердить введя `PARTING_START`

Во время создания размеченного диска будет запрошено подтверждение на создание новых крипто-контейнеров. Нужно будет подтвердить введя `YES`, для каждого контейнера, а также задать им
несложные пароли (3 ввода пароля для каждого контейнера, 2 раза -- ввод + подтверждение для создания контейнера, 3ий для его открытия).


Если в файле `iso2/create_default_parted_gpt.sh` будут изменения, то размеченный образ диска нужно будет пересоздать этим же скриптом: `./create_parted_qcow2.sh`



## Запуск тестирования
`./qemu_start.sh` - тестирование установки на систему с uefi

`./reset_and_start.sh` - тестирование установки на систему с uefi, со сбросом состояния виртуального диска (с сохранением базовой разметки для для тестирования)

`./qemu_start_bios.sh` - тестирование установки на систему с legacy bios (планируется добавить в будущем)

`./reset_and_start.sh --legacy` - тестирование установки на систему с legacy bios, со сбросом состояния виртуального диска (с сохранением базовой разметки для для тестирования, ключ планируется добавить в будущем)

Самый свежий образ установочного диска Arch Linux будет автоматически скачен через протокол Bittorrent. Но только либо при первом запуске, либо если имеющийся образ уже устаревший. Если он уже есть, то можно его заранее поместить в каталог, можно в виде ссылки, но с обязательным сохранением оригинального имени файла.

## После запуска qemu
Нужно последовательно ввести следующие команды:
```bash
mkdir /mnt/sr0
mount /dev/sr0 /mnt/sr0
cd /mnt/sr0
./RUN_ALL.sh
cd ../i<tab><enter>
```
После чего можно будет запустить установку, введя команду `./INSTALL.sh` + опциональные ключи при необходимости.

## Ключи для INSTALL.sh
`--log` логгирование установки в файл log.txt

`--no-cache-mirrors` принудительно обновить зеркала, через reflector с сортировкой по скорости

`-i <id>`, `-s <id>`, `-d <id>`, `-o <id>` установка по id из xml-файла заранее (можно не задавать через ключ, а указать с ходе выполнения установки)

`--cache-qemu-pkgs` получение пакетов из кеша хоста (см. ниже) также с этим ключом отключается любые действия по настройке зеркал в гостевой системе чтобы не тратить лишнее время на то, что не будет использоваться

## Получение пакетов из кеша хоста
Для того чтобы при тестировании на qemu не приходилось каждый раз заново скачивать пакеты из интернета, можно получать их из кеша хоста. Для этого нужно сделать следующее:
1. Установить из AUR пакет `pacserve` при помощи paru, yay или любого другого AUR-менеджера.
2. Запустить под рут-правами скрипт `./use_cashing_in_host.sh`. В данный момент он реализован только для Arch Linux с systemd, доработка под Artix будет позже.
3. Запустите один из скриптов: `./qemu_start.sh` или `./reset_and_start.sh` Для загрузки с прошлым состоянием виртуального диска или его сброса соответственно.
4. Для работы кеширования при установке в гостевой системе нужно запустить файл `./INSTALL.sh` с ключом `--cache-qemu-pkgs`.
