Да, можно настроить кэширование пакетов для установки Arch Linux, чтобы каждый раз не скачивать их из интернета. Вот несколько подходов для создания локального кэша пакетов:

### 1. Использование `pacman`-кэша на локальном компьютере (рекомендуется)

Если у вас уже есть загруженные пакеты в кэше `pacman` на основном компьютере, можно поделиться ими с виртуальной машиной. Пакеты по умолчанию хранятся в директории `/var/cache/pacman/pkg`. Для этого:

1. **Создайте общую директорию для пакетов**:
   - Создайте временную папку, например, `~/archlinux-pkg-cache`.
   - Скопируйте туда все текущие пакеты из кэша `pacman`:

     ```bash
     mkdir -p ~/archlinux-pkg-cache
     cp -r /var/cache/pacman/pkg/* ~/archlinux-pkg-cache
     ```

2. **Подключите папку с пакетами к QEMU в режиме `virtio`**:
   - Используйте опцию `-virtfs` для подключения папки в качестве общего ресурса:

     ```bash
     qemu-system-x86_64 \
         -enable-kvm \
         -m 2G \
         -cpu host \
         -smp 2 \
         -drive file=archlinux_vm_disk.qcow2,format=qcow2 \
         -virtfs local,path=~/archlinux-pkg-cache,mount_tag=pkgcache,security_model=none \
         -nic user,model=virtio-net-pci \
         -vga virtio
     ```

3. **Подмонтируйте кэш на виртуальной машине**:
   - В виртуальной машине можно смонтировать общую папку с помощью `mount`:

     ```bash
     mkdir /mnt/pkgcache
     mount -t 9p -o trans=virtio pkgcache /mnt/pkgcache
     ```

4. **Настройте `pacman` для использования локального кэша**:
   - Создайте симлинк из кэша в систему:

     ```bash
     ln -s /mnt/pkgcache /var/cache/pacman/pkg
     ```

Теперь `pacman` будет использовать пакеты из вашего локального кэша и не будет повторно загружать их, если они уже там есть.

### 2. Создание локального зеркала с помощью `nginx` или `python -m http.server` 

Если у вас много пакетов, можно создать локальный HTTP-сервер для раздачи пакетов:

1. **Настройте локальный HTTP-сервер**:
   - В каталоге с пакетами запустите HTTP-сервер на Python (например, на порту 8080):

     ```bash
     cd ~/archlinux-pkg-cache
     python3 -m http.server 8080
     ```

2. **Добавьте локальный репозиторий в `pacman.conf`**:
   - В виртуальной машине отредактируйте `/etc/pacman.conf` и добавьте локальное зеркало:

     ```ini
     [localrepo]
     SigLevel = Optional TrustAll
     Server = http://10.0.2.2:8080
     ```

     *(Замените `10.0.2.2` на IP-адрес хоста, если он отличается)*.

### 3. Использование `pacman` в режиме кэширующего прокси с `cower` или `pacserve`

Для более гибкого решения можно настроить `pacserve` — локальный кэширующий прокси-сервер для `pacman`, который автоматически раздаёт пакеты, имеющиеся на вашем компьютере.

1. **Установите `pacserve`**:

   ```bash
   sudo pacman -S pacserve
   ```

2. **Запустите `pacserve` на хосте**:

   ```bash
   sudo systemctl start pacserve
   ```

3. **Настройте виртуальную машину для использования `pacserve`**:
   - Отредактируйте `/etc/pacman.d/mirrorlist` на виртуальной машине, добавив ваш хост как зеркало:

     ```ini
     Server = http://10.0.2.2:15678/$repo/os/$arch
     ```

Теперь виртуальная машина будет сначала проверять локальный кэш `pacserve`, прежде чем пытаться загрузить пакеты из интернета.

### 4. Создание собственного локального репозитория

Если вам нужно протестировать конкретные версии пакетов или минимизировать доступ к внешним серверам, вы можете создать локальный репозиторий.

1. **Соберите нужные пакеты в одной папке**, например `~/myrepo`.
2. **Создайте индекс репозитория**:

   ```bash
   repo-add ~/myrepo/custom.db.tar.gz ~/myrepo/*.pkg.tar.zst
   ```

3. **Подключите этот репозиторий**:
   - Добавьте его в `/etc/pacman.conf`:

     ```ini
     [custom]
     SigLevel = Optional TrustAll
     Server = file:///home/user/myrepo
     ```

4. Теперь `pacman` будет использовать ваш локальный репозиторий.

### Заключение

Эти методы помогут вам экономить трафик и ускорить тестирование, используя кэширование пакетов локально. Выбор подхода зависит от частоты тестирования и объёма пакетов, необходимых для установки.
