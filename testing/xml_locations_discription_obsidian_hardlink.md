## Для новых точек монтировая

***todo**: возможно, стоит унифицировать названия самих тегов и названия полей ассоциативного массива из скрипта, но данная задаче не первоочередная*

Теги, которые всегда обязательны:
- **location  (mount_point)** -- точка монтирования
- **way (type)** -- одно из возможных 4х значений, которые описаны ниже
- **crypt_mode** -- список возможных значений зависит от type
Также должны быть заданы некоторые другие обязательные теги,
но какие именно зависит от значений **type** и **crypt_mode**

Опициональных тегов по сути нет, они либо обязательны в определённых конкретных случаях, в зависимости от **way** и **crypt_mode**, либо их указывать не нужно 
### Типы

#### format_ext4
##### общее описание

Нужно использовать с осторожностью т.к. данные указанном по **uuid** разделе будут удалены, т.к. данные на выбранном разделе удаляются, он может быть любым как пустым свежесозданным так и с любой файловой системой и данными,
но на этом месте в данном кейсе создаётся именно раздел с ext4
##### опции шифрования 

Возможные значения **crypt_mode**:
- **none** - форматируем раздел и создаём новый ext4
- **pwd** - форматируем раздел и создаём новый luks (у пользователя запрашивается пароль для создания), новые ext4 создаётся внутри свежесозданного luks
- **file** - форматируем раздел и создаём новый luks, для шифрования которого используется кейфайл, которой должен быть расположен по указанному пути, если по данному пути пусто, то на этом месте будет создан новый кейфайл

##### дополнительные обязательные теги

Остальные обязательные теги:
- Всегда обязательно:
	- **uuid**  -- uuid раздела, который будет отформатирован в ext4 или luks - всегда обязателен для данного типа. ВАЖНО: при использовании шифрование нужно указать uuid раздела в основной разметке, который будет отформатирован в luks, а не uuid раздела внутри luks'а  
- Опционально:
	- **keyfile** -- обязательный тогда и только тогда  когда **crypt_mode**=*file*


#### new_subvol_in_btrfs
##### общее описание

Для указанной точки монтирования в процессе установки будет создан новый сабволюм на разделе с btrfs в основной разметке диска, который должен быть создан до запуска установочного скрипта. При этом не имеет значения есть ли в данном btrfs-разделе уже другие сабволюмы или нет. 
*todo: проверка гарантированного свободного места в указанном btrfs в процессе реализации*
При использовании шифрования, в основной разметке диска должен находиться заранее созданный luks, внутри которого должен быть заранее созданный btrfs.
Крипто-контейнер luks, при использовании  данного типа раздела для точки монтирования, открывается в процессе установки (если он закрыт). Поэтому пользователь во время установки либо должен знать пароль от него либо при **crypt_mode**=*file* должен быть указан путь к действующему кейфайлу (в отличие от  **format_ext4** создание нового кейфайла в данном кейсе не предусмотрено).

##### опции шифрования 

Возможные значения **crypt_mode**:
- **none** - создаём новый сабволюм в заранее созданном разделе с btrfs в основной разметке диска
- **pwd** - создаём новый сабволюм в заранее созданном разделе с btrfs btrfs в заранее созданном luks, который в свою очередь находится в основной разметке диска, в процессе установки luks нужно открыть по паролю (если он закрыт)
- **file** - создаём новый сабволюм в заранее созданном разделе с btrfs btrfs в заранее созданном luks, который в свою очередь находится в основной разметке диска. В процессе установки luks нужно открыть действующим кейфайлом путь к которому нужно обязательно указать в настройках (т.к. создание нового luks тут не предусмотрено, создание нового кейфайла точно также не предусмотрено).
##### дополнительные обязательные теги

Остальные обязательные теги:
- Всегда обязательно:
	- - **uuid**  -- uuid заранее созданного btrfs раздела (или luks с btrfs внутри), где будет создаваться новый сабволюм
	- **subvolume**  -- название нового сабволюма, который будет создан (принято именовать начиная с @), не должен совпадать с уже имеющимися сабволюмами в целевом btrfs
- Опционально:
	- **keyfile** -- обязательный тогда и только тогда  когда **crypt_mode**=*file*


#### new_subvol_in_btrfs_in_lvm
##### общее описание

Данный случай похож на предыдущий, но только раздел с btrfs (созданный заранее) должен находиться не в основной разметке диска, а должен быть логическим томом lvm (в заранее созданной группе томов). Также настройки шифрования здесь намного сложнее (будет описаны ниже).

##### опции шифрования 

Возможные значения **crypt_mode**:
- **none_in_none** - создаём новый сабволюм в заранее созданном разделе с btrfs, который является заранее созданным логическим томом в заранее созданной группе томов
- **pwd_in_none** - создаём новый сабволюм в заранее созданном разделе с btrfs, лежащим внутри luks, который является заранее созданным логическим томом в заранее созданной группе томов 
- **file_in_none** - всё аналогично **pwd_in_none**, с отличием в том, что в процессе установке luks открывается (если он не открыт) не через пароль, а через заранее созданный кейфайл (должен быть обязательно заранее созданным т.к. в данном случае работа происходит также с заранее созданным luks)
- **none_in_pwd** - создаём новый сабволюм в заранее созданном разделе с btrfs, который является заранее созданным логическим томом в заранее созданной группе томов, в которую входят физические тома (один или несколько) внутри luks которые должен быть указан по uuid. Если luks'ов в pv lvm внутри несколько, то их uuid'шники нужно разделить при помощи запятой. ВАЖНО! включение в эту группу других незашифрованных pv приведёт к дыре в безопасности.
- **none_in_file** - интуитивно понятный микс фич уже описанных в **none_in_pwd** и **file_in_none**

##### дополнительные обязательные теги

Остальные обязательные теги:
- Всегда обязательно:
	- **lv-volume**  -- полный путь к девайсу заранее созданного логического тома lvm в виде или btrfs раздела (или luks с btrfs внутри), где будет создаваться новый сабволюм
	- **subvolume**  -- название нового сабволюма, который будет создан (принято именовать начиная с @), не должен совпадать с уже имеющимися сабволюмами в целевом btrfs
- Опционально:
	- **keyfile** -- обязательный тогда и только тогда  когда **crypt_mode**=*file_in none или none_in_file*
	- **pv-volumes-uuids**   --  обязательный тогда и только тогда  когда **crypt_mode**=*none_in_file или none_in_pwd* (*старый тег pv-volume был заменён на этот новый*) -- один или несколько разделённых запятой uuid от pv lvm, входящего(входящих) в целевую группу томов. ВАЖНО! включение в эту группу других незашифрованных pv приведёт к дыре в безопасности. Если luks'ов с pv lvm несколько, то в режиме **none_in_file** поддерживается только один keyfile на все эти luks, пароли же в режиме **none_in_pwd** можно использовать разные

#### new_ext4_in_lvm
##### общее описание

Чем то похож на **format_ext4**, но в отличие от него заведомо не удаляет никаких данных. В процессе установки, создается новый логический том c ext4 или luks с ext4 внутри в случаях: **pwd_in_none** и **file_in_none**.
##### опции шифрования 

Возможные значения **crypt_mode**:
- **none_in_none** - создаём новый логический том в заранее созданной группе томов (в которой неn логического тома с таким именем, он будет создан в процессе установки), на данном логическом томе с прописанным настройках размером будет файловая система ext4 в незашифрованном виде 
- **pwd_in_none** - создаём новый логический том в заранее созданной группе томов (в которой не логической тома с таким именем, он будет создан в процессе установки), на данном логическом томе с прописанным настройках размером будет крипто-контейнер luks c ext4 внутри. Пароль к этому luks потребуется задать в процессе установки.
- **file_in_none**  - создаём новый логический том в заранее созданной группе томов (в которой не логической тома с таким именем, он будет создан в процессе установки), на данном логическом томе с прописанным настройках размером будет крипто-контейнер luks c ext4 внутри. Путь к созданному или ещё не созданному кейфайлу нужно прописать с настройках, если его не по указанному пути, то он будет создан автоматически.
- **none_in_pwd** - здесь внутри luks располагается не логический том lvm, а физический, в отличие от **file_in_none** и **pwd_in_none** luks (один или несколько) с физическим томом (или томами) нужно создать до запуска скрипта. luks (один или несколько) открываются на начальной стадии работы скрипа паролем (или паролями) которые должны быть известны пользователю. Логический же том как в случае **none_in_none** в процессе работы скрипта создаётся в голым ext4, не завёрнутым в luks. Двойное одновременное шифрование и физических и логических томов lvm не реализовано из коробки как слишком избыточное (но недокуменнтированная и непротестированная возможность такого двойного шифрования судя по всему есть: просто заluksованные физические тома нужно открыть заранее, до запуска скрипта и работать с ними как незашифрованными pv lvm). 
- **none_in_file** - аналогично **none_in_pwd** только luks (один или несколько) с pv lvm открывается (открываются) не по паролю а через прописанный путь к кейфайлу, в отличии от способа открытия по паролю данный кейс подразумевает единый кейфайл, на несколько pv lvm целевой группы если их несколько. В отличие от **file_in_none** и **pwd_in_none** создание нового кейфайла (если его не будет по указанному пути) не предусмотрено. Он должен обязательно быть создан заранее т.к. luks (один или несколько) т.к. не создаются в процессе установки и должны быть созданы заранее. 

##### дополнительные обязательные теги

Остальные обязательные теги:
- Всегда обязательно:
	- **lv-volume**  -- полный путь к девайсу логического тома lvm в которой должен быть создан в процессе установки (в отличие от случаев с btrfs его не нужно создавать заранее, иначе будет ошибка, что такой логический том уже существует)
	- **size** -- размер запланированного к созданию логического тома с ext4 или luks, скрип также автоматически проверят хватает ли для всех планируемых к созданию логических тома места в соответствующих им группах томов
- Опционально:
	- **keyfile** -- обязательный тогда и только тогда  когда **crypt_mode**=*file_in none или none_in_file*
	- **pv-volumes-uuids**   --  обязательный тогда и только тогда  когда **crypt_mode**=*none_in_file или none_in_pwd*  -- один или несколько разделённых запятой uuid от pv lvm, входящего(входящих) в целевую группу томов. ВАЖНО! включение в эту группу других незашифрованных pv приведёт к дыре в безопасности. Если luks'ов с pv lvm несколько, то в режиме **none_in_file** поддерживается только один keyfile на все эти luks, пароли же в режиме **none_in_pwd** можно использовать разные

## Для уже существующих точек монтирования (extra)

Теги, которые всегда обязательны:
- **location  (mount_point)** -- точка монтирования, которая уже существует
- **way (type)** -- одно из возможных 4х значений, которые описаны ниже, значения для extra отличаются от того что было для new
- **crypt_mode** -- список возможных значений зависит от type, тут уже всё по аналогии с new
Также должны быть заданы некоторые другие обязательные теги,
но какие именно зависит от значений **type** и **crypt_mode**

### Типы

для уже существующих разделов возможные значения type отличаются:
- **partition** - для уже существующих разделов в основной разметке gpt (или msdos, после добавления поддержки legacy bios)
- **subvol_in_btrfs** - для уже существующих сабволюмов в btrfs
- **subvol_in_btrfs_in_lvm** - для уже существующих сабволюмов в btrfs, которые находятся в lvm
- **volume_in_lvm** - для уже существующих томов в lvm

для partition (точно также на volume_in_lvm), filesystem лучше опредяелять автоматически т.к. файловая система не создаётся, а используется уже существующая. Кроме ext4 можно добавить поддержку ntfs. А также fat32, f2fs, xfs, ext3, ext2 и т.д.
Если там btrfs, то нужно указать пользователю, исправить настройки в xml

Примечание: если я решу добавить поддержку zfs, то для неё нужно будет добавить пополнительные типы аналогично btrfs, в том числе и для точек монтирования new, а не только для extra.

### Опции шифрования

Для partition и subvol_in_btrfs возможные значения crypt_mode: none, pwd, file.
Для *_in_lvm возможные значения crypt_mode: none_in_none, none_in_pwd, none_in_file, pwd_in_none, file_in_none.

### Дополнительные обязательные теги

- **subvolume** - обязательный тег для subvol_in_btrfs и subvol_in_btrfs_in_lvm, указывает на имя сабволюма, который будет использоваться.
- **keyfile** - обязательный тег для file (file_in_none, none_in_file) в crypt_mode, указывает на путь к кейфайлу, который будет использоваться.
- **lv-volume** - обязательный тег для *_in_lvm, указывает на путь к девайсу логического тома lvm, который будет использоваться.
- **pv-volumes-uuids** - обязательный тег для *_in_lvm с crypt_mode=none_in_file или none_in_pwd указывает на uuid pv lvm, который будет использоваться, теоритически может быть несколько, но достаточно одного.
- **uuid** - обязательный тег для partition и subvol_in_btrfs, указывает на uuid раздела, который будет использоваться.

### Теги, которые были в new, но нет в extra
- **size** - никогда не используется в extra, т.к. размер уже существующего раздела не меняется. В new он используется для создания нового логического тома с ext4 или luks с ext4 внутри.
